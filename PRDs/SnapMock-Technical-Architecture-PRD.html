Document Overview

Purpose

This document defines the technical architecture for SnapMock, an open-source, cross-platform screenshot annotation and UI mockup tool. It serves as the authoritative reference for all implementation decisions and is intended to be consumed by Claude Code (or equivalent AI coding agents) to produce detailed implementation plans.

Scope

SnapMock provides layered vector and raster annotation capabilities on top of imported raster images (screenshots or loaded files). The primary use case is rapid UI mockup creation: users capture or import a screenshot, then cut, paste, move, and annotate screen regions to prototype interface changes. This PRD covers the internal software architecture only. UI layout, individual annotation tool behaviors, and screen capture are covered in separate PRDs.

Design Principles

  • Layered, non-destructive editing: all annotations and raster selections remain independently editable until explicitly flattened.
  • Cross-platform first: Linux (primary), Windows, and macOS from a single codebase using PyQt6.
  • Open source friendly: clear module boundaries, minimal coupling, well-documented interfaces, permissive licensing (MIT or Apache 2.0).
  • Performance: smooth interaction at 4K resolution with 100+ annotation objects and multiple raster layers.
  • Extensibility: new annotation tools can be added without modifying core subsystems.

Working Project Name

The project is tentatively named SnapMock. This name is subject to change pending trademark verification. All code references should use a configurable application name constant.

System Architecture Overview

Architectural Pattern

SnapMock uses a Model-View-Controller (MVC) variant built on top of Qt's QGraphicsScene/QGraphicsView framework. The scene graph serves as both the model (object storage and spatial indexing) and the view coordination layer. A separate document model tracks layer ordering, metadata, and project state.

High-Level Component Map

The system is composed of the following major subsystems, each of which is detailed in Section 3:

Dependency Flow

Dependencies flow downward. UI widgets depend on managers, managers depend on the scene graph and data models, and data models have no upward dependencies. Communication from lower layers to upper layers uses Qt signals exclusively.

  • UI Widgets (Toolbar, LayerPanel, PropertyPanel) depend on ToolManager, LayerManager, SelectionManager
  • ToolManager depends on SnapScene, CommandStack, SelectionManager
  • LayerManager depends on SnapScene, CommandStack
  • SelectionManager depends on SnapScene
  • CommandStack depends on Data Models only
  • Data Models (Layer, AnnotationItem, Project) have zero upward dependencies

Core Subsystems

Scene Graph Engine

Overview

The scene graph is the backbone of SnapMock. It is built on QGraphicsScene/QGraphicsView, which provides hardware-accelerated rendering, spatial indexing via BSP trees, built-in hit testing, and z-value ordering. SnapMock extends these classes to add layer-aware rendering, tool event routing, and custom item types.

SnapScene (extends QGraphicsScene)

Functional requirements:

  • Maintain a background raster layer (the imported screenshot or blank canvas) rendered as a QGraphicsPixmapItem at z-value 0.
  • Support adding, removing, and reordering QGraphicsItem subclasses that represent annotation objects.
  • Route all mouse press, move, release, and key events to ToolManager before default handling.
  • Provide a canvasSize property (QSizeF) that defines the document bounds, independent of the viewport.
  • Emit signals: itemAdded(item), itemRemoved(item), itemModified(item), sceneRectChanged(rect).
  • Support scene-level grid snapping with configurable grid size (default 10px, toggleable).
  • Provide a method to flatten all visible layers to a single QImage for export.

SnapView (extends QGraphicsView)

Functional requirements:

  • Zoom: ctrl+scroll wheel zoom from 10% to 3200%, with smooth animated transitions. Display current zoom level in status bar.
  • Pan: middle-mouse-button drag for panning, or spacebar+left-click drag. Support two-finger trackpad pan on macOS.
  • Fit-to-window: keyboard shortcut (Ctrl+0) to fit the entire canvas in the current viewport.
  • Pixel-level zoom: at zoom levels above 800%, render a pixel grid overlay.
  • Cursor: update cursor icon based on the active tool and hover context (resize handles, move, crosshair, etc.).
  • Rulers: optional horizontal and vertical pixel rulers along the edges of the viewport, toggled via View menu.
  • Crosshair guides: optional crosshair lines following the cursor, toggled via View menu.

Item Base Class (SnapGraphicsItem)

All annotation objects inherit from SnapGraphicsItem, which is a QGraphicsItem subclass (or QGraphicsObject for signal support). It adds the following properties and behaviors to every item in the scene:

PropertyTypeDescription
layer_idUUIDReference to the Layer this item belongs to. Used by LayerManager for visibility and lock state.
item_idUUIDGlobally unique identifier for this item. Used for serialization and command references.
lockedboolIf True, item cannot be selected, moved, or edited. Mirrors the parent layer lock state OR per-item lock.
visibleboolIf False, item is not rendered. Mirrors the parent layer visibility OR per-item visibility.
opacityfloat (0.0-1.0)Item-level opacity, multiplied with layer opacity during rendering. Used by non-vector items (Blur, Highlighter, Stamp, Emoji). VectorItem subclasses use fill_opacity and stroke_opacity instead (see Section 4.3).
blend_modeenumBlend mode for compositing (Normal, Multiply, Screen, Overlay, etc.). Default: Normal.
metadatadictExtensible key-value store for tool-specific properties (stroke color, font, arrow style, etc.).
creation_orderintMonotonically increasing integer assigned at creation. Used as tiebreaker for z-ordering within a layer.

Functional requirements:

  • Override boundingRect() and paint() per item type.
  • Override shape() to return an accurate QPainterPath for hit testing (not just bounding rect).
  • Implement serialize() and deserialize(data) for project save/load. Serialization format is JSON.
  • Implement clone() for copy/paste operations that returns a deep copy with a new item_id.
  • Respect layer lock and visibility states: if the parent layer is locked, ignore all interactive events.
  • Support interactive property editing: when selected, emit a signal with the item's editable properties so the PropertyPanel can display appropriate controls.

Layer Management System

Layer Data Model

Each Layer is a lightweight data object (not a QGraphicsItem) that groups items and controls their collective rendering behavior.

PropertyTypeDefaultDescription
layer_idUUIDauto-generatedUnique identifier.
namestr"Layer N"User-editable display name.
visibleboolTrueToggles rendering of all items in this layer.
lockedboolFalsePrevents selection, movement, or editing of any item in this layer.
opacityfloat1.0Layer-level opacity (0.0 to 1.0). Applied multiplicatively with item opacity.
blend_modeenumNormalCompositing blend mode for the entire layer.
layer_typeenumAnnotationOne of: Background, Annotation, RasterRegion. Background is always at z-index 0.
orderintautoPosition in the layer stack. Lower = rendered first (behind). Managed by LayerManager.
itemslist[UUID][]Ordered list of item_ids belonging to this layer.

LayerManager

The LayerManager is a singleton that owns the ordered list of Layer objects and synchronizes layer state with the scene graph.

Functional requirements:

  • Create layer: add a new layer at a specified position in the stack (or top by default). Assign unique name. Emit layerAdded(layer) signal.
  • Delete layer: remove a layer and all its items from the scene. Must not allow deletion of the last remaining layer. Emit layerRemoved(layer_id) signal. This operation is undoable.
  • Reorder layers: move a layer to a new position in the stack. Update z-values of all affected items in the scene. Emit layersReordered() signal.
  • Duplicate layer: deep-copy a layer and all its items (with new UUIDs). Insert the duplicate directly above the source layer.
  • Merge layers: flatten two or more selected layers into one. Vector items from upper layers are rasterized onto the lower layer's composite. This is destructive and undoable.
  • Toggle visibility: set layer.visible and update all child items' visibility in the scene. Emit layerVisibilityChanged(layer_id, visible).
  • Toggle lock: set layer.locked and update all child items' lock state. Emit layerLockChanged(layer_id, locked).
  • Set opacity: update layer.opacity and trigger scene repaint. Emit layerOpacityChanged(layer_id, opacity).
  • Active layer: track which layer is currently active (receives new annotation items). Only one layer can be active at a time. Emit activeLayerChanged(layer_id).
  • Flatten all: composite all visible layers into a single raster image, replacing all layers with one Background layer containing the result. Destructive and undoable.
  • Z-value management: maintain a mapping from layer order to z-value ranges. Each layer is allocated a range of 10,000 z-values (layer 0 = 0-9999, layer 1 = 10000-19999, etc.). Items within a layer use their creation_order as offset within the range.

Layer Panel (UI Contract)

The Layer Panel is a dockable widget. Its visual design is covered in the UI PRD, but its functional contract with LayerManager is defined here:

  • Display all layers in stack order (top layer at top of panel).
  • Each layer row shows: visibility eye icon (toggle), lock icon (toggle), thumbnail preview (48x48, updated on item changes), layer name (double-click to rename), opacity slider (on hover or expand).
  • Support drag-and-drop reordering of layers within the panel.
  • Right-click context menu: Duplicate Layer, Delete Layer, Merge Down, Merge Visible, Flatten All, Layer Properties.
  • Active layer is highlighted. Clicking a layer row makes it active.
  • Multi-select layers with Ctrl+click for batch operations (delete, merge, lock, hide).

Tool Engine & Registry

ToolManager

The ToolManager is a singleton that manages the currently active tool, routes input events from SnapScene to the active tool, and maintains the tool registry.

Functional requirements:

  • Maintain a registry of all available tools, keyed by tool_id string.
  • Activate a tool by tool_id. Deactivate the previous tool (calling its deactivate() method) before activating the new one. Emit toolChanged(tool_id) signal.
  • Route mouse events (press, move, release, double-click) and key events from SnapScene to the active tool's corresponding handler methods.
  • Provide the active tool with references to: SnapScene, SelectionManager, LayerManager, CommandStack, and the PropertyPanel interface.
  • Support tool-specific cursors: when a tool is activated, set the viewport cursor to the tool's declared cursor.
  • Support tool-specific options: each tool declares a list of configurable options (e.g., stroke color, line width, font). These are displayed in a ToolOptionsBar below the main toolbar.
  • Support temporary tool override: holding a modifier key (e.g., Space for pan, Alt for eyedropper) temporarily switches tools without changing the toolbar selection. Releasing the modifier returns to the previous tool.

Selection & Transform System

SelectionManager

The SelectionManager tracks which items are currently selected and provides operations on the selection set.

Functional requirements:

  • Single select: clicking an item with the Select tool selects it and deselects all others. Emit selectionChanged(selected_ids) signal.
  • Multi-select: Shift+click adds/removes an item from the selection. Ctrl+click toggles. Rubber band selection (drag on empty canvas) selects all items whose shapes intersect the rubber band rectangle.
  • Select all: Ctrl+A selects all unlocked, visible items on the active layer. Ctrl+Shift+A selects all unlocked, visible items across all layers.
  • Deselect: Escape or clicking empty canvas deselects all. Emit selectionCleared() signal.
  • Selection filtering: only items on unlocked, visible layers can be selected.
  • Selection info: provide methods to query the selection: count(), items(), boundingRect(), containsType(type).
  • Group operations: move, delete, copy, cut, align, distribute operations can be applied to the entire selection set.

TransformHandles

When one or more items are selected, a TransformHandles overlay is drawn around the collective bounding box. This overlay provides interactive resize, rotate, and skew operations.

Handle layout:

  • Eight resize handles: four corners and four edge midpoints. Corner handles maintain aspect ratio when Shift is held; edge midpoints resize in one axis only.
  • Rotate handle: a circular handle connected by a line above the top-center of the bounding box. Dragging rotates all selected items around the bounding box center. Shift constrains rotation to 15-degree increments.
  • Move: dragging anywhere inside the bounding box (but not on a handle) moves all selected items. Shift constrains movement to horizontal or vertical axis.
  • Skew: holding Ctrl while dragging an edge midpoint handle applies a skew transform.
  • All transforms are previewed in real-time during drag and committed as a single undoable command on mouse release.

Alignment & Distribution

When multiple items are selected, alignment and distribution operations are available via the toolbar or context menu:

  • Align: left, center, right, top, middle, bottom. Aligns to the bounding box of the selection set or to the canvas.
  • Distribute: horizontal spacing, vertical spacing. Evenly distributes items across the selection bounding box.
  • All alignment/distribution operations are single undoable commands.

Raster Operations Pipeline

Purpose

Raster operations enable the core UI mockup workflow: selecting pixel regions from the background screenshot (or any raster layer), cutting or copying them, and pasting them as independent, movable raster layer items. This is the primary differentiator from simple annotation tools.

Raster Selection Tool (Rectangle)

Functional requirements:

  • Draw a rectangular marching-ants selection on the canvas by click-and-drag.
  • The selection is pixel-based and operates on the composite raster of all visible layers below the active layer (or a configurable source: active layer only, all visible layers, or a specific layer).
  • Once a selection is drawn, the user can: Move the selection marquee (click inside and drag). Resize the selection marquee (drag handles). Copy the selected pixels to clipboard (Ctrl+C). Cut the selected pixels (Ctrl+X): removes pixels from the source and places them on clipboard. Paste as new layer item (Ctrl+V): creates a new RasterRegionItem from clipboard content, positioned at the original selection location or at canvas center.
  • Pressing Enter or double-clicking inside the selection confirms it and creates a RasterRegionItem on the active layer.
  • Pressing Escape cancels the selection.
  • Shift constrains the selection to a square. Alt draws the selection from center.
  • Display selection dimensions (width x height in pixels) near the selection marquee.

Raster Selection Tool (Freeform / Lasso)

Functional requirements:

  • Draw a freeform closed path by click-and-drag. The path auto-closes on mouse release.
  • All other behaviors are identical to the rectangle raster selection, except the selection mask is the filled freeform path rather than a rectangle.
  • The resulting RasterRegionItem stores both the pixel data and an alpha mask derived from the freeform path.

RasterRegionItem (extends SnapGraphicsItem)

A RasterRegionItem is a scene item that holds a raster pixel region extracted from another layer. It is the result of a raster cut/copy/paste operation.

PropertyTypeDescription
pixmapQPixmapThe pixel data of the extracted region.
alpha_maskQBitmap (optional)For freeform selections, the mask that defines the non-rectangular boundary.
source_rectQRectFThe original location and size in scene coordinates where the pixels were extracted from.
source_layer_idUUIDThe layer from which the pixels were extracted (for potential undo reconstruction).

Functional requirements:

  • Renders the pixmap (with optional alpha mask) at its scene position.
  • Supports all standard transforms: move, resize (with interpolation), rotate.
  • Supports opacity and blend mode (inherited from SnapGraphicsItem).
  • Serializable: on save, the pixmap is stored as an embedded PNG in the project file.
  • On cut: the source pixels in the source layer are replaced with transparency (or configurable fill color). This modification is recorded as part of the undoable cut command.

Crop Tool

Functional requirements:

  • Displays a resizable crop overlay on the canvas. Area outside the crop is dimmed with a semi-transparent overlay.
  • Crop handles on all four edges and corners. Shift constrains to original aspect ratio.
  • Rule-of-thirds grid overlay inside the crop area (toggleable).
  • Pressing Enter confirms the crop: the canvas size is reduced, and all items are repositioned relative to the new origin. This is a single undoable command.
  • Pressing Escape cancels the crop.
  • Display crop dimensions in pixels near the crop area.

Clipboard & Drag-Drop System

ClipboardManager

The ClipboardManager handles both internal (within SnapMock) and external (system clipboard) copy/paste operations.

Functional requirements:

  • Copy vector items: serialize selected SnapGraphicsItems to an internal MIME type (application/x-snapmock-items) containing JSON. Also place a rasterized PNG on the system clipboard for interoperability with other applications.
  • Copy raster selection: place the selected pixel region on the system clipboard as a PNG image. Also store internally with metadata (source layer, source rect) for richer paste behavior.
  • Paste from internal clipboard: deserialize items from the internal MIME type. Place them at the center of the current viewport with a small offset from the original position (cascade paste). Assign new UUIDs. Add to the active layer.
  • Paste from system clipboard: if the system clipboard contains an image, create a new RasterRegionItem from it and add to the active layer at viewport center. If it contains text, create a TextItem.
  • Cut: copy (as above) then delete the selected items. For raster selections, copy the pixels then replace the source with transparency. Both operations are recorded as a single undoable command.
  • Duplicate (Ctrl+D): shortcut that copies and immediately pastes with a small (10px, 10px) offset. Single undoable command.

Drag and Drop

Functional requirements:

  • Accept image files (PNG, JPG, BMP, GIF, WebP, SVG) dragged from the OS file manager. Create a RasterRegionItem (or SVG item) on the active layer at the drop position.
  • Accept images dragged from web browsers (URL or inline image data).
  • Support internal drag-and-drop of items between layers (drag from canvas, drop on layer panel row).
  • Support dragging items from the stamp/sticker library onto the canvas.

Command / Undo-Redo System

CommandStack

All state-changing operations are recorded as Command objects on the CommandStack, enabling unlimited undo/redo.

Functional requirements:

  • Push a command: execute the command's redo() method and add it to the stack. Clear the redo history (any commands after the current position).
  • Undo: call the current command's undo() method. Move the stack pointer back. Emit undoPerformed(command_description) signal.
  • Redo: call the next command's redo() method. Move the stack pointer forward. Emit redoPerformed(command_description) signal.
  • Macro commands: support grouping multiple commands into a single undoable unit (e.g., cut = copy + delete). MacroCommand.undo() calls each sub-command's undo() in reverse order.
  • Dirty flag: track whether the document has been modified since last save. The dirty flag is set when a command is pushed and cleared when the document is saved.
  • Memory management: optionally cap the undo history at a configurable maximum (default: 200 commands). When the cap is reached, the oldest command is dropped.
  • Emit signals: canUndoChanged(bool), canRedoChanged(bool), undoTextChanged(str), redoTextChanged(str) for UI binding.
  • Keyboard shortcuts: Ctrl+Z for undo, Ctrl+Shift+Z (or Ctrl+Y) for redo.

Command Interface

Every command implements:

MethodDescription
redo()Execute (or re-execute) the operation. Must be idempotent.
undo()Reverse the operation, restoring previous state exactly.
description()Return a human-readable string (e.g., "Move 3 items", "Add Arrow") for display in Edit menu.
merge_with(other)Optional. If the new command can be merged with the previous (e.g., incremental text typing), return True and absorb the other command. Used to coalesce rapid small edits.

Rendering Pipeline

Display Rendering

For on-screen display, QGraphicsView handles rendering via its built-in scene traversal. SnapMock augments this with:

  • Layer opacity: before rendering, each item's effective opacity is computed as item.opacity * layer.opacity (for non-vector items) or item.fill_opacity / item.stroke_opacity * layer.opacity (for vector items). This is applied via QPainter alpha modulation during the item's paint() call.
  • Layer visibility: invisible layers have all their items hidden via QGraphicsItem.setVisible(False).
  • Blend modes: for Normal blend mode, Qt's default compositing is used. For non-Normal blend modes, the layer is rendered to an offscreen QImage first, then composited onto the below layers using QPainter.setCompositionMode().
  • Selection overlay: selected items are drawn with a dashed blue outline and resize handles on top of normal rendering.
  • Tool overlays: active tools may draw temporary overlays (selection marquee, crop region, guide lines) on a dedicated overlay layer that is always on top.

Export Rendering

For file export, the ExportRenderer composites all visible layers into a final QImage (for raster formats) or QPainter-based output (for vector formats).

Functional requirements:

  1. Create a QImage at the target DPI and canvas size.
  2. For each visible layer in bottom-to-top order: if the layer has Normal blend mode, render all its items directly onto the QImage using QPainter. If the layer has a non-Normal blend mode, render the layer to a temporary QImage, then composite it using the specified blend mode.
  3. For vector export (SVG/PDF), render vector items using their native QPainter paths. Raster items are embedded as images.
  4. Selection overlays, guides, grid, and other UI elements are excluded from export.

A tool preset and a tool theme (General UI PRD Sections 5.2, 11.8, 11.9) are user data, not document state: they are never part of a project file and never on the command stack. Both hold creation defaults, the dictionary every tool keeps as BaseTool.creation_defaults, and only the tools that have creation defaults have presets.

Storage. The application data directory is the platform's generic configuration location (QStandardPaths) under a lower-case snapmock folder: ~/.config/snapmock on Linux. Under it: presets/<tool_id>/*.json, one file per preset (format_version, tool_id, name, values); themes/*.json, one file per user theme in the .smktheme schema; and tool_state.json, the active theme's name and, per tool, the applied preset and the current values, written after every change and read at startup (the last-used tool option values of General UI PRD Section 15.4; Phase 7 decision 7.1, option B). File names are a slug of the name; the name inside the file is authoritative.

The .smktheme schema. A JSON object with "format": "smktheme", format_version (1), name, app_version, and tools, a map of tool id to encoded creation defaults. Import and export copy this document unchanged; a reader refuses a newer format_version and skips a value it cannot decode. Values are encoded by type: colours as {"$color": "#AARRGGBB"}, alignment flags as {"$alignment": int}, the text and callout enumerations as {"$enum": name, "value": value}, and numbers, booleans, and strings as themselves.

Event Routing Order

Mouse and keyboard events from QGraphicsView follow this routing chain:

  1. SnapView receives the raw QEvent and translates to scene coordinates.
  2. SnapScene.event() passes the event to ToolManager.handleEvent().
  3. ToolManager passes the event to the active tool's corresponding handler (mouse_press, etc.).
  4. If the tool returns True (consumed), event propagation stops.
  5. If the tool returns False (not consumed), default QGraphicsScene behavior applies (item selection, item drag, etc.).

Plugin & Extension Architecture

Design Goal

New annotation tools and export formats should be addable without modifying core code. The plugin system is designed for internal extensibility first (adding tools in the main repo) and external plugin loading second (future phase).

Tool Plugin Interface

Any class that inherits from BaseTool and implements the required interface (Section 3.3.2) can be registered with ToolManager. The registration process is:

  1. Create a new Python module in the tools/ package (e.g., tools/my_custom_tool.py).
  2. Define a class that inherits from BaseTool and implements all abstract methods.
  3. In the module's register() function, call ToolManager.register_tool(MyCustomTool).
  4. Add the module to the tool loading list in config/tools.json or by placing it in a plugins/tools/ directory that is auto-scanned at startup.

Export Plugin Interface

Export formats follow a similar pattern. An export plugin implements a BaseExporter class with methods: export(scene, layers, filepath, options) and get_format_info() returning supported extensions and descriptions. Exporters are registered with the Exporter registry and automatically appear in the File > Export menu.

Future: External Plugin Loading

In a future phase, SnapMock will support loading plugins from a configurable directory (default: ~/.snapmock/plugins/). Each plugin is a Python package with a manifest.json describing its entry points, minimum application version, and dependencies. This is deferred to a post-1.0 release.

Acceptance Criteria

The technical architecture is considered complete and validated when the following criteria are met:

Scene Graph

  1. A SnapScene can be instantiated with a configurable canvas size and background color.
  2. A 4K PNG image can be loaded as the background layer and rendered in SnapView.
  3. Zoom (10%-3200%), pan, and fit-to-window work smoothly at 60 FPS with a 4K background.
  4. Pixel grid overlay appears at zoom levels above 800%.
  5. Grid snapping constrains item positions to the configured grid size when enabled.

Layers

  1. Layers can be created, deleted, reordered, duplicated, and merged.
  2. Layer visibility toggle immediately shows/hides all items in the layer.
  3. Layer lock toggle prevents selection and modification of all items in the layer.
  4. Layer opacity slider smoothly adjusts the composite opacity of all items in the layer from 0% to 100%.
  5. Z-ordering correctly renders layers in stack order: items in higher layers always appear above items in lower layers.

Tools & Items

All 18 tools listed in Section 3.3.3 are registered and selectable. Each tool creates its corresponding item type on the active layer. Items can be selected, moved, resized, and rotated using TransformHandles. All tool operations produce undoable commands.

Raster Operations

A rectangular raster selection can be drawn on the canvas. The selected pixel region can be copied (Ctrl+C), cut (Ctrl+X), and pasted (Ctrl+V) as a new RasterRegionItem. The pasted item can be moved and resized independently. Cut operations leave transparency in the source area. All operations are undoable.

File I/O

A project with 50 items across 5 layers and a 4K background can be saved to .smk format and reloaded with 100% fidelity (all item positions, properties, layer states, and raster data are preserved). Export to PNG and JPG produces correct flattened output. The dirty flag accurately tracks unsaved changes.

Cross-Platform

The application launches and passes all acceptance tests on Ubuntu 22.04, Windows 10, and macOS 12 without any platform-specific code paths (beyond Qt's internal handling).

Performance

All performance targets in Section 8 are met on a mid-range system (4-core CPU, 16 GB RAM, integrated GPU).
