## Starting state, verified at commit 36de493 on 09-09-26

- **First run.** Nothing of Section 16 exists: no Welcome panel, no first-launch detection, no "Don't show this again" flag. Help > Welcome / Getting Started is a message box saying the panel arrives with the first-run work. The settings store has no first-run key; `capture/onboardingShown` is the one first-time flag and the precedent. The default tool configuration of Section 16.2 matches the code for the active tool, stroke colour, fill colour, stroke width, font, grid size, and hidden rulers, and differs on two lines: the PRD says snap enabled and the code's `view/snapToGrid` default is off; the PRD says Theme: System and the code's `appearance/theme` default is light (the Phase 3 row says the System option falls back to light where the style hint is unknown, which is not the same thing).
- **The three cards' actions exist as menu routes.** Open an Image is `_file_import_image`; Paste from Clipboard is `_edit_paste`, which routes a system image through `_paste_system_image`; New Blank Canvas has two candidates, `_file_new` (an unsaved Untitled tab at the default canvas size, no dialog) and `_library_new_canvas` (an auto-saved Library file at the default canvas size, no dialog). Neither opens a canvas size dialog, which Section 16.1 asks the card to do; the Resize Canvas dialog of Section 11.4 is the size-dialog precedent.
- **Accessibility.** Accessible names exist only where Phases 6 and 7 set them as they built: the Property Panel (28), the colour picker (10), the Manage Presets and Tool Themes dialogs (9), the Layer Panel (4), the Preferences dialog (2), the preset dropdown, the Active Theme label, and the collapsible section header. Nothing in the menu bar, the Main Toolbar, the Left Tool Palette, the Tool Options Bar's shared controls, the status bar, the document tabs, the Library panel, the Export dialog, or the Keyboard Shortcuts, About, and Find/Replace Color dialogs has one. No `setAccessibleDescription` anywhere. `setTabOrder` and `setFocusPolicy` appear twice in the whole package; the Section 14 tab order (Menu Bar > Main Toolbar > Tool Options Bar > Left Tool Palette > Canvas > Layer Panel > Property Panel) is not set. The two style sheets give line edits, spinboxes, combo boxes, key-sequence edits, and push buttons a 2 px accent border on focus; tool buttons, lists, trees, the canvas view, dock titles, and the tab bar have no focus rule. Status bar hints change through `SnapStatusBar.set_hint` with no accessibility event. Locked layers show the lock icon and a dimmed row; selected items show the accent handles and a dashed outline; both satisfy the "colour is not the only indicator" bullet. No test computes contrast for the theme tables.
- **Responsive behaviour.** The minimum size is 1024 by 600 (Phase 1). Nothing happens at that size: the right panel stack does not collapse to icon-only, and the Tool Options Bar relies on `QToolBar`'s own extension button when it overflows, which is an overflow menu in effect but not by design. No collapse thresholds, no narrow (200 px) or icon-strip (48 px) mode for the Layer Panel and Property Panel, no popover from an icon-strip thumbnail, no Preferences rows for the thresholds. The Left Tool Palette is a 48 px single column (Phase 4) and satisfies Section 15.2's third bullet as it stands. The Layer Panel has a 200 px minimum width (Phase 6).
- **Multi-monitor.** The main window's geometry goes through `QWidget.restoreGeometry`, which Qt already moves onto a connected screen when the saved rectangle is off every screen. Floating dock widgets are restored by `restoreState` with no such check; a panel saved on a disconnected monitor comes back off-screen. Nothing records which monitor a floating panel was on.
- **Unsaved Changes.** `_ask_unsaved_changes` builds a `QMessageBox` with the Section 11.7 wording and Save, Don't Save, Cancel (Phase 1). It has no canvas preview; a `QMessageBox` cannot hold one, so the preview means a small `QDialog` of the same wording. The dialog is exercised by `tests/test_window_layout.py` through a stand-in for `_ask_unsaved_changes`, and the `main_window` fixture marks every document clean before close so the dialog never blocks the suite.
- **Session persistence.** Every Section 15.4 line is done except the last: `AppSettings.zoom_level` exists and nothing reads or writes it; the recent-files list is a list of paths with no per-file metadata. Zoom per recent project needs either a metadata record beside each recent path or a settings key per path.
- `tests/conftest.py` points `AppSettings` at an empty INI file and the tool data directory at a temporary folder for every test. Under it every test is a first run: a Welcome panel shown on first launch will appear in every `MainWindow` a test creates unless the fixture, or the window, has a way to suppress it. Decide that in step 2 before the panel exists, or the whole suite changes shape.

## Decisions to surface

Apply the two-part test from the global guidance. One decision is expected to pass it; present it with the consequential decision template before step 2 and wait:

- **5. Welcome panel's New Blank Canvas card.** Section 16.1 says the card "opens canvas size dialog". Options: the card creates a Library canvas, as Library > New Canvas does, so the first thing a new user makes is auto-saved and never prompts on close, matching the 09-07-26 Library decision; or the card creates an unsaved document, as File > New does, so the first thing a new user makes behaves like every other File > New tab. Under either, decide whether the card opens a size dialog first (the PRD says so; neither route does today) or takes the default canvas size like both routes, and record it.

Everything else follows the PRD; where the PRD is silent, decide, note it under Deviations, and continue. Nine silences are known: where the Welcome panel lives (a page swapped into the central widget above the document stack, a panel over the first tab, or a dialog; the PRD says "instead of the empty canvas"); how "no QSettings found" is detected once earlier versions have written settings (a first-run key, as the capture onboarding flag is), and what the test fixture does about it; whether the two Section 16.2 lines the code differs on (snap enabled, Theme: System) change the settings defaults for everyone or only what a first run writes; what "abbreviated controls" means for the Property Panel in narrow mode and what the icon-strip popover holds; which Preferences category takes the three thresholds; whether the Tool Options Bar's overflow is `QToolBar`'s extension button, named and tested, or a menu of the bar's own; how a status bar message reaches a screen reader (an accessibility event on the zone, or the zone as a live region through its accessible description); what the contrast test measures (the Section 13 table pairs, both themes, 4.5:1 for text and 3:1 for large text); and where the per-project zoom is stored (metadata beside each recent path, or a settings key per path, and whether a Library file's zoom is stored the same way).

## Standards that apply

- Terminology Precision, Writing Register, and Reply Format from the global guidance apply to every reply and to the documents.
- Every new module gets a row in Technical Architecture PRD Section 10 in the commit that creates it, and any new package or top-level module also bumps that PRD's version.
- Departures from the General UI PRD are recorded in its change log with a version bump, not only in code comments.
- All mutations of document state go through commands; a Welcome panel action that creates or imports goes through the existing route, never a new one.
- No control is disabled (General UI PRD 1.3); the Welcome panel's cards check their requirements through `check_requirements` and show the unmet message (Paste from Clipboard with an empty clipboard, for one).
- Every new control gets an accessible name as it is created; step 3 audits everything built before this phase and does not skip a module because it is large.
- Slots connected to the process-wide `ThemeManager` must be bound methods of a `QObject`, never lambdas; avoid Python reference cycles between a widget and its children.
- `uv run ruff check .`, `uv run ruff format .`, `uv run mypy snapmock`, and `uv run pytest` must pass before each commit, with `QT_QPA_PLATFORM` set to `offscreen` for pytest.
- No new runtime dependency without surfacing it as a decision.
- Commit messages end with the attribution block the session provides.
